# Tri Coach — контекст проекта

## Зачем этот проект
Учебно-боевой пет-проект Ардака (Senior Java backend, 10+ лет). Цель — прокачать **Java, Spring Boot, базу, облако (AWS), CI/CD и эксплуатацию в проде** через настоящий продукт, доведённый до продакшена. Ардак сам первый пользователь: готовится к триатлону 70.3.

## Главный фокус — пробелы из фидбека Revolut (ноябрь 2026)
Кодинг похвалили: TDD, чистая архитектура, уточнение требований. Не хватило глубины в эксплуатации:
1. **Production database management** — бэкапы и восстановление, пул соединений, медленные запросы, VACUUM/bloat.
2. **Schema migration strategies** — миграции без простоя (expand → contract), откат, бэкфилл.
3. **Advanced indexing** — составные, покрывающие, частичные индексы, `EXPLAIN ANALYZE` на реальном объёме.
4. **Proactive observability** — метрики, трейсинг, логи, которые показывают проблему до жалоб.
5. **Scalable monitoring & alerting** — SLO, алерты по симптомам, runbook.
6. **Deployment resilience** — health-пробы, graceful shutdown, rolling/blue-green, откат, таймауты/ретраи/circuit breaker.

**Поэтому в каждой задаче есть обязательный блок «Эксплуатация».** Задача не закрыта, пока он не сделан.

## Продукт
Приложение для любителя с работой, который готовится к старту 70.3. Главный вопрос: **«Успеваю ли я к старту и что поменять на этой неделе?»**
1. **Обратный отсчёт до старта** — гонка с датой, фазы (база → развитие → пик → подводка), план против факта.
2. **Форма и усталость** — TSS каждой тренировки, CTL / ATL / TSB, прогноз финиша по дисциплинам.
3. **Анализ «кирпичей» (brick)** — бег сразу после вела, потеря темпа против свежего бега.
4. **ИИ-разбор недели** — LLM получает агрегаты и пишет разбор. Вишенка, а не ядро.

## Источники данных и ограничения — ВАЖНО
- Данные — только собственные файлы пользователя: **FIT** (основной), позже GPX/TCX.
- **Strava API не используем** (его правила запрещают передавать данные в ИИ). Неофициальные библиотеки с логином в Garmin Connect — нельзя.
- В LLM уходят **только агрегаты**, не сырые потоки и не персональные данные.
- Источник данных — **порт с адаптерами**: ручная загрузка → Telegram-бот → (если одобрят) вебхук Garmin. Ядро не знает, откуда файл.
- Повторная загрузка того же файла **идемпотентна**: SHA-256 содержимого + уникальное ограничение в базе.
- Название и тексты: «70.3 / half-distance», **не** «Ironman» (торговая марка).

## Стек
Java 21, Spring Boot (актуальная стабильная со start.spring.io), Spring Data JPA, PostgreSQL, Flyway, Testcontainers, JUnit 5, AssertJ, Mockito, Docker Compose, Garmin FIT SDK (Java).
Наблюдаемость: Spring Boot Actuator, Micrometer, Prometheus, Grafana, OpenTelemetry, структурные логи.
Позже: S3 + SQS (локально LocalStack), Resilience4j, Spring AI, GitHub Actions, AWS (ECR, ECS Fargate, RDS, Secrets Manager, CloudWatch), Terraform, k6, Telegram Bot API.

## Глоссарий домена
- **Activity** — тренировка: вид спорта (SWIM / BIKE / RUN / OTHER), старт, длительность, дистанция, средний пульс, мощность/темп.
- **TSS** — нагрузка тренировки (hrTSS / rTSS / TSS по мощности). Формула — решение в ADR.
- **CTL** — «форма», экспоненциальное среднее дневной нагрузки за ~42 дня. **ATL** — «усталость», за ~7 дней. **TSB** — «свежесть» = CTL − ATL (на конец предыдущего дня).
- **Brick** — бег, начатый не позже чем через 15 минут после окончания вела.
- **Race** — целевой старт: дата, дистанция, целевое время.

## Формат задачи
Карточка: цель → требования → **тесты первыми** → **эксплуатация** → критерии готовности → подсказки (по просьбе) → вопрос для интервью. После выполнения — код-ревью, чек-лист, запись в журнал и в «Истории для интервью», затем следующая задача.

## Чек-лист эксплуатации (на каждое ревью)
- [ ] Как я узнаю, что это сломалось? (метрика / лог / алерт)
- [ ] Миграция совместима с предыдущей версией приложения? Как её откатить или пережить откат приложения?
- [ ] Какие запросы к базе добавились? Есть план (`EXPLAIN`) и нужный индекс?
- [ ] Что будет при повторе / параллельном вызове / падении посередине?
- [ ] Есть таймауты на внешние вызовы?

## Дорожная карта
Каждый шаг: **Код** + **Эксплуатация**.

0. **Скелет**
   - Код: Spring Boot, Postgres в Docker Compose, Flyway, Testcontainers, сущность `Activity` + тест репозитория.
   - Эксплуатация: Actuator health с группами liveness/readiness, `/actuator/prometheus`, Prometheus + Grafana в Compose. Правило миграций: только вперёд, всегда совместимы с предыдущей версией.
1. **Загрузка FIT**
   - Код: эндпоинт загрузки, разбор через FIT SDK, дедупликация по хешу, тест на параллельную загрузку.
   - Эксплуатация: свои метрики (загрузки по результату, таймер разбора), структурные логи с correlation ID (MDC), первый дашборд в Grafana.
2. **Нагрузка**
   - Код: TSS, CTL/ATL/TSB как чистые функции по TDD.
   - Эксплуатация: **генератор данных** — годы тренировок, тысячи атлетов, миллионы строк. Первый `EXPLAIN ANALYZE` на запросе дневной нагрузки.
3. **Неделя и гонка**
   - Код: `Race`, фазы, план против факта, keyset-пагинация истории, N+1 на экране недели.
   - Эксплуатация: **лаба по индексам** (составной, покрывающий `INCLUDE`, частичный; до/после), `pg_stat_statements`, размер пула Hikari. **Лаба по миграциям**: переименовать колонку без простоя в 3 релиза (expand → migrate → contract), бэкфилл батчами, `CREATE INDEX CONCURRENTLY` во Flyway (нетранзакционная миграция), `lock_timeout`.
4. **Brick-анализ**
   - Код: потоки данных (records/laps), поиск пар вел→бег, потеря темпа.
   - Эксплуатация: большая таблица записей — партиционирование по месяцам, retention, наблюдение за bloat и VACUUM.
5. **Асинхронный приём**
   - Код: S3 + SQS, воркер, ретраи с backoff и jitter, DLQ, идемпотентный консьюмер.
   - Эксплуатация: **SLO** «95% файлов обработаны за 60 секунд», метрики возраста сообщений и глубины DLQ, алерты по симптомам, трейсинг через весь конвейер (OpenTelemetry), первый **runbook**.
6. **CI/CD**
   - Код: GitHub Actions — тесты на PR, сборка и пуш образа.
   - Эксплуатация: прогон миграций в CI на копии схемы, тег образа = commit SHA, откат = деплой предыдущего тега.
7. **AWS + Terraform**
   - Код: ECS Fargate, RDS, Secrets Manager, домен, HTTPS.
   - Эксплуатация: бэкапы RDS и **учебное восстановление (PITR)**, дашборды и алармы CloudWatch, rolling-деплой с health checks и deployment circuit breaker, graceful shutdown.
8. **ИИ-разбор недели**
   - Код: Spring AI, промпт из агрегатов, структурированный ответ, тесты с фейковой моделью, модель за интерфейсом.
   - Эксплуатация: таймауты, ретраи, circuit breaker (Resilience4j), фолбэк без ИИ, метрика расходов и лимит.
9. **Прод-качество и учения**
   - Код: Telegram-адаптер для загрузки файлов.
   - Эксплуатация: нагрузочный тест (k6), **game day**: убить таск, сломать миграцию, забить очередь — сработали ли алерты? Разбор в формате постмортема.
